PCB Analysis

In this lab, you will go through some of the processes of analyzing different common parts of a development board that are open to potential hardware attacks.

Reverse Engineering a PCB

In order to analyse a PCB, you need to know how to follow a trace from the component to the chip in order to learn how it will communicate. When using a chip in PCB design, you will only have the pin numbers along with the software that you can use to program the MCU. Engineers do not typically have a development board that is the same for all devices, so learning how to correlate a chip to a PCB and what that looks like on a schematic is crucial to hardware attacks.

Three words worth knowing tonight:

  • Pad. Exposed copper rectangles (typically) that is exposed for componenets to be soldered on to.
  • Trace. Copper that connects two or more copper pads under neath the coating.
  • Via. A copper circle cutout that connects different layers of a PCB together.
  • Chip. Any IC or MCU device (normally a black square/rectangle) on a PCB.

Analysis 1 · USB Interface

For this first part of the lab, you will need to determine the pins that allow for UART communication from your laptop to the MCU on the board

  1. Determine the pin number of the Data Minus (D-) from the USB to the MSP432E401 chip
  2. Determine the number of vias that the D- trace goes through before connecting with the MSP432E401 chip
  3. Determine the pin number of the Data Plus (D+) from the USB to the MSP432E401 chip
  4. Determine the number of vias that the D+ trace goes through before connecting with the MSP432E401 chip
  5. You the will create the final flag for the USB Interface in hexadecimal as followed: 
    hcig{DataPlusPin_DataPlusVias_DataMinusPin_DataMinusVias}

If you are confused, please let a mentor or us know.

Reveal flag
hcig{5E_02_5D_02}

Analysis 2 · User Buttons

For this second part of the lab, pins that the the buttons are connected to on the board.

  1. Determine the pin that the RST pin is connected to.
  2. Determine the pin that the S1 or User Button 1 is connected to.
  3. Determine the pin that the S2 or User Button 2 is connected to.
  4. Determine what the vias are connected to on one side of the vias.
  5. You the will create the final flag for the all of the buttons will be in hexadecimal as followed: 
    hcig{RSTPin_UserButton1_UserButton2_ViaConnection}

If you are confused, please let a mentor or us know.

Reveal flag
hcig{6_37_20_GND}

Analysis 3 · LED Diagnosis

For this third and final part of this lab, you will need to know a little about LEDs. LEDs are very sensitive to current, which if a resistor is not put in series with it, the LED will more than likely explode...

Knowing that now, you will need that information for this part of the lab. You will need to know the number of resistors and LEDs in order to get the last flag.

  1. Determine the number of LEDs that there are on the PCB
  2. Determine the number of resistors that are connected to the LEDs
  3. Total all of the resistor values.
  4. You the will create the final flag for all of the above should be in hexadecimal as followed: 
    hcig{LEDCount_ResistorCount_ResistorTotal}

If you get stuck, ask a facilitator. Bring the flags you find so we can record them.

Reveal flag
hcig{05_07_AC8}
